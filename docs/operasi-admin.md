# Backup, pemulihan, dan operasi admin

**Database & Pemulihan** menampilkan pengukuran kesiapan, riwayat migrasi, daftar artefak terenkripsi, antrean, fase, durasi, dan hasil. Permintaan biasa selesai dicatat tanpa menunggu proses di host. Progres menampilkan fase yang sudah dicapai worker. Worker hanya menerima operasi yang telah ditentukan dan mengambil satu pekerjaan per putaran dengan penguncian PostgreSQL. Penjadwalan default memakai timer systemd pada host Compose yang dipasang oleh operator. Pengujian memakai PostgreSQL lokal dan data sintetis.

## Persiapan worker pada host

1. Jalankan migrasi dari root Madevi-Site menggunakan role migrasi. Worker memakai Node.js 24 dan klien PostgreSQL yang kompatibel dengan server serta koneksi PostgreSQL langsung dari lingkungan yang sama dengan aplikasi. Gunakan `DATABASE_URL` dengan role operasi pada host. Untuk pg_dump, isi `MADEVI_BACKUP_DATABASE_URL` dengan role baca pada database yang sama. Siapkan `MADEVI_BACKUP_DIR` mode `0700`, `MADEVI_BACKUP_KEY` dengan 64 digit heksadesimal acak, dan ruang disk. [Role database dan pembuatan kunci](../ops/backup-restore.md#siapkan-akses-direktori-dan-kunci)
2. Siapkan database kosong dengan nama `madevi_restore_latihan` bila restore akan digunakan. Batasi jaringan dan koneksinya ke operator. Isi `MADEVI_RESTORE_DATABASE_URL` hanya pada worker host. Simpan seluruh kredensial di berkas env privat atau pengelola rahasia. Setel `TMPDIR` ke filesystem host yang privat dan terenkripsi untuk proses dekripsi.
3. Untuk unduhan dari admin, salin [contoh mount](../ops/compose.download.example.yml) menjadi `compose.download.yml` pada root checkout host. Pastikan arsip privat dapat dibaca UID proses web melalui mount baca-saja. Variabel `MADEVI_BACKUP_DOWNLOAD_DIR` menunjuk lokasi mount di container. Secret backup dan akses Docker tetap pada host worker. Sertakan override tersebut pada pemanggilan Compose awal dan saat mengganti container.
4. Jalankan `npm run jobs:operations` dari root dengan environment worker, atau pakai `node --env-file=/lokasi-privat/worker.env scripts/run-operations.mjs`. Periksa panel dan lihat waktu laporan worker, target yang terkonfigurasi, serta ruang penyimpanan. Gunakan [timer systemd](../ops/systemd/README.md) untuk memasang jadwal pesan, operasi, backup rutin, retensi, dan alarm bila diaktifkan. Probe worker membaca `http://127.0.0.1:3000`, port loopback jalur Compose default.

Jika worker berhenti, status lama tetap dapat dibaca. Panel menandai sampel kedaluwarsa setelah 10 menit. Worker berikutnya menandai pekerjaan yang terputus sebagai gagal. Tinjau target dan hasil aktual sebelum mengajukan ulang. Pengajuan admin yang gagal perlu diperiksa sebelum diajukan ulang. Jika browser kehilangan respons saat mengajukan, gunakan **Periksa permintaan yang terputus**. Pengiriman ulang memakai ID asli dan meminta kata sandi lagi. Simpan log host dengan rotasi untuk mendiagnosis putaran yang tidak dapat menyimpan hasil karena database tidak tersedia.

## Backup, verifikasi, unduh, dan restore

1. Masuk sebagai admin utama dengan MFA, buka **Database & Pemulihan**, pilih **Buat backup**, masukkan ulang kata sandi, lalu ajukan. Lihat fase pembuatan dump dan verifikasi. Status selesai berarti file telah dienkripsi dan tag autentikasinya lolos.
2. Pilih artefak dari daftar. **Pilih untuk verifikasi** membuka formulir pemeriksaan ulang tag. **Unduh terenkripsi** mengirim file terenkripsi melalui sesi admin yang telah memenuhi MFA. Simpan kuncinya di tempat terpisah. Jika file, kunci, atau direktori berubah, jalankan verifikasi dan periksa izin atau salinan sebelum mencoba ulang.
3. Pilih **Periksa target restore**. Hasil harus menyatakan database terpisah kosong dan tanpa koneksi lain. Pilih **Restore database** dan artefak sumber. Periksa nama target dan dampak di panel. Ketik teks konfirmasi yang memuat target, ID hasil pemeriksaan, serta ID artefak. Hasil pemeriksaan berlaku 10 menit untuk pengajuan. Worker memeriksa lagi target, memverifikasi arsip, dan menulis dalam transaksi PostgreSQL.
4. Setelah status selesai, cocokkan data, checksum migrasi, dan berkas. Antrean operasional yang belum selesai dari snapshot ditutup pada target. Pesan terjadwal snapshot dibatalkan pada target agar tidak terkirim ulang. Data utama dan koneksi aplikasi tetap ditangani terpisah oleh operator. Untuk pemeriksaan lengkap dan retensi, gunakan [prosedur pemulihan](../ops/backup-restore.md).

Bila gagal, pilih **Siapkan percobaan ulang** dari riwayat dan konfirmasi kembali. Satu pekerjaan gagal memberi satu percobaan ulang baru, yang juga dapat ditinjau jika gagal. Untuk restore, periksa target baru yang benar sebelum mencoba lagi. Berkas cadangan tidak dihapus otomatis.

## Pulihkan pengaturan dan rilis

Gunakan **Riwayat versi dan pemulihan** pada Halaman & Navigasi atau Pengaturan Website. Pilih **Bandingkan versi** dan baca perbedaan bidang. Pemulihan menulis versi baru serta identitas admin. Konflik versi meminta pemuatan ulang. Riwayat mulai dari nilai yang tersedia saat migrasi atau saat perubahan pertama. Revisi konten tetap tersedia melalui editor konten.

Untuk operasi host, jalur default mendukung profil CPU/memori container serta pergantian image lokal. Environment, koneksi database, DNS, secret, dan konfigurasi proxy tetap dikelola operator di host. Profil yang ditampilkan tidak memuat nilai rahasia.

1. Salin [contoh katalog](../ops/host-catalog.example.json) ke lokasi privat di host, mode `0600`. Tentukan direktori operasi mode `0700`, nama project Compose aktual, ID image lokal yang immutable dari `docker image inspect`, daftar migrasi yang didukung tiap image, dan profil CPU/memori. Buat ID baru jika isi profil berubah. Worker memakai Docker lokal melalui `/var/run/docker.sock`. Jalankan worker dengan akun operator yang diizinkan, di luar container aplikasi.
2. Masukkan jalur katalog sebagai `MADEVI_HOST_CATALOG` pada environment worker. Jalankan `npm run ops:prepare -- current normal` di root untuk mencatat profil awal dan menghasilkan `compose.override.json`. Pilih ID yang benar-benar sedang aktif atau yang telah disetujui untuk konfigurasi awal. Perintah ini hanya membuat berkas. Pada deployment yang kelak diotorisasi, gunakan Compose default, nama project yang sama dan override itu. Jika mengaktifkan unduhan, tambahkan `compose.download.yml` sebelum override profil.
3. Dari panel pilih **Ganti rilis** atau **Terapkan profil host**, lalu pilih arsip yang dibuat setelah migrasi terakhir dan masih berumur kurang dari 24 jam. Periksa target, versi skema, dan nilai profil. Ketik konfirmasi dan verifikasi ulang kata sandi.
4. Worker memeriksa ulang skema dan artefak. Worker menjalankan service `madevi` memakai image yang sudah ada, memeriksa ID image container, serta probe live dan ready. Jika gagal, worker mencoba mengembalikan profil sebelumnya dan menjalankan pemeriksaan yang sama. Jika keduanya gagal, buka log Compose pada host dan periksa container yang aktif serta override. Permintaan berikutnya perlu diajukan ulang setelah kondisi host dipastikan. Jika `switch.lock` tertinggal, pastikan proses lama sudah berhenti dan cocokkan container, override, serta profil aktif sebelum operator melepas lock.
5. Perubahan image tidak mengembalikan migrasi atau data. Image lama dengan skema yang berbeda ditolak. Siapkan pemulihan database tersendiri bila rilis lama membutuhkan skema lama.

Restore, perubahan image, dan profil host memerlukan sesi MFA asal yang masih aktif ketika worker mengambil pekerjaan. Jika pekerjaan lama ditolak, periksa kondisi target dan cadangan, lalu ajukan ulang dari sesi aktif. Hasil worker juga masuk audit. [Keamanan host](keamanan.md#batas-kepercayaan-dan-akses)

## Baca monitoring

**Statistik & Monitoring** membedakan status proses, kesiapan PostgreSQL, sampel host, antrean, dan kejadian gangguan. Tabel request memakai status akhir handler dan durasi hingga header siap, pada route yang dilabeli. Jumlah 4xx dipisah dari 5xx. Angka mencakup 24 keranjang jam UTC termasuk jam berjalan. Waktu terakhir dan rentang ditampilkan dengan waktu lokal browser. Trafik yang dihentikan proxy, akhir transfer unduhan, dan route lain berada di luar pengukuran ini. Retensi standar menawarkan calon pembersihan metrik per jam yang lebih lama dari tujuh hari. Aktifkan mode `prune` hanya setelah meninjau hasil `dry-run`.

Probe host mengukur live dan ready secara terpisah. CPU, memori, dan filesystem dibaca oleh worker dengan cakupan host yang menjalankannya. Sampel gagal atau belum ada diberi status yang sesuai. Kejadian disimpan dari transisi probe atau pekerjaan gagal sampai pulih. Jeda heartbeat dicatat saat worker kembali. Pantau journal saat database atau worker sendiri tidak dapat menulis. Alarm opsional mengecek readiness dari host dan menyimpan status pada direktori privat di luar database. [Alarm dan kondisi pemulihan](../ops/systemd/README.md#alarm-smtp-dan-respons-gangguan)
